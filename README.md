# JS Bytecode Compiler

Experimental toolchain that parses JavaScript source code, compiles it into a custom bytecode representation, and wraps the result in a lightweight emulator template. The generated bundles can optionally be obfuscated and minified for distribution.

## Prerequisites
- Node.js 16 or newer
- npm 7+

## Quick Start
1. Install dependencies:
   ```bash
   npm install
   ```
2. Build the TypeScript sources and emulator template:
   ```bash
   npm run build
   ```
3. Convert a script (defaults shown):
   ```bash
   npm run compile
   ```
   The default command reads `input/in.js` and writes `out/in.bytecode.js` plus `out/in.bytecode.min.js`.
   The sample script emits verbose progress logs and a summary so you can quickly verify execution.

## CLI Usage
After running `npm run build`, invoke the compiler with:
```bash
npm run compile -- --input path/to/source.js --out ./output/dir
```

### Available options
- `-i, --input <path>`: JavaScript file to compile. Defaults to `input/in.js`.
- `-o, --out <dir>`: Destination directory. Defaults to `./out` (created automatically).
- `--no-minify`: Skip the obfuscation/minification pass and only emit the main bundle.
- `-h, --help`: Display usage information.

The output directory receives two files (unless `--no-minify` is set):
- `<name>.bytecode.js` – emulator template populated with the compiled bytecode.
- `<name>.bytecode.min.js` – obfuscated and minified variant.
File names inherit the base name of the input source (e.g., `input/foo.js` ↦ `out/foo.bytecode.js`).

## Using the returned function
- The VM now runs the bytecode once at load time and expects the program to return a callable value.
- That callable is exposed as `vm` on `globalThis`, via `module.exports`, and as the IIFE result bound to `bytecodeVm` in the generated bundle (because Rollup emits `var bytecodeVm = (function(){...}());`).
- If the bytecode entrypoint does not return a function, the VM will throw during bootstrap.
- The default sample (`input/in.js`) returns a handshake/XOR helper; after compiling you can call `mathFunction(clientSeed, serverSeed, salt)` to get the masked packet bytes.
- Usage examples with the compiled bundle:
  - Browser script tag: `<script src="./out/in.bytecode.js"></script>` then `const xorFunction = window.bytecodeVm;`.
  - Node/CommonJS: `const xorFunction = require("./out/in.bytecode.js");`
  - ES module: `import xorFunction from "./out/in.bytecode.js";`
  - DevTools paste: `const xorFunction = (function(){ /* paste the full contents of in.bytecode.js here */ });` (the pasted code returns the function).

## Development Notes
- Any changes under `src/` require rerunning `npm run build` before converting code.
- `npm start` is an alias for `node dist/index.js`; pass the same CLI flags after `--`.
- The emulator template bundle is generated at `dist/EmulatorTemplate/EmulatorTemplate.js` via Rollup (`npm run bundle:esm`).
- To experiment with the template alone, inspect `src/Emulator.ts` and related helpers.
- The parser currently targets ES5 syntax; prefer `var` declarations and avoid modern keywords like `const` and `let` in sample inputs.

## Project Layout
- `src/`: TypeScript sources for the parser, bytecode emitter, emulator, and CLI entry point.
- `dist/`: Build artifacts generated by `npm run build`.
- `input/`: Sample JavaScript input (`in.js`) used by the default command.
- `out/`: Generated bundles (created on demand).
